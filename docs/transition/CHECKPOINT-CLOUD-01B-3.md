## Resultado de la migración

**Restauración y validación funcional completadas en Supabase.** La API de ensayo se ejecutó localmente en loopback con el rol restringido. Al terminar se cerró ese proceso de prueba. El PostgreSQL local de referencia sigue aceptando conexiones.

- El cliente Docker autenticó la conexión al pooler de sesión con CA oficial y `sslmode=verify-full`. PostgreSQL 17.11 devolvió `ssl=false` en `pg_stat_ssl` para el tramo que ve el servidor detrás del pooler. El cliente verificó CA y hostname en su conexión al pooler. El proceso Node con el rol runtime también conectó con verificación de CA y hostname.
- Se pasó el comando shell como argumento de Docker y se verificaron las opciones activas de `set -eu`. Los SQL temporales se escribieron en UTF-8 sin BOM, se montaron en solo lectura y se retiraron al terminar. `pg_restore --exit-on-error` generó el SQL y `psql -X -w -v ON_ERROR_STOP=1 --single-transaction` aplicó roles, objetos, filas y asociación del despliegue en una sola transacción.
- Se instaló pgvector **0.8.2 en `public`**. PostgreSQL administrado ignoró la versión explícita y utilizó la predeterminada. Una guarda comprobó la versión y el esquema antes del commit. Se conservaron las referencias vectoriales existentes.
- Se restauraron `banuchat`, `banuchat_auth` y `banuchat_academic` con los objetos del inventario de 36 tablas y 21 funciones. Se crearon `cloud_runtime` con login y `cloud_provision` y `banuchat_auth_executor` sin login. El restore inicialmente falló al asignar propietarios de funciones. La primera corrección de inserción SQL tuvo un error de escape. Ambas transacciones se revirtieron. La tercera otorgó CREATE temporal al ejecutor en los dos esquemas requeridos y lo retiró al cerrar, junto con la membresía temporal del migrador.
- Se retiraron del runtime los permisos de actualización de identidades y verificadores y los grants de recuperación inactiva heredados del dump. Los roles `anon`, `authenticated`, `service_role` y `authenticator` tienen cero accesos USAGE efectivos sobre los tres esquemas. El guard del rol real pasó y el SELECT académico directo devolvió 42501. El rol runtime pasó la prueba advisory con dos conexiones, contención tras COMMIT y adquisición por la segunda después de liberar.
- SQL confirmó **2 releases listas, 32 estudiantes, 62 intentos, 8 recursamientos, 120 vectores de 1024 dimensiones, 5 citas restauradas y 60 claves foráneas validadas**. El hash de IDs, vectores y hashes de chunks coincide con el laboratorio (`82c166849bad9cc3d26677ab60bd464ae182d2f62747692996593324c8802b5a`). `runtime_scope` quedó asociado a la base `postgres` y a un UUID nuevo. La guarda verificó cero sesiones y refresh tokens importados antes del commit.
- La API v2 inició con el perfil administrado. Pasaron login histórico y U+8, sesión propia, progreso, lectura académica por sesión, historial restaurado, cinco citas recuperadas y descarga de artefactos con sus hashes. Otra cuenta recibió 404. SHA-256 `b8d1e2cf3c0894ddb6c242cb66dc09bc6a143c1b87df5fa7841bf3563c42ce24`. La conciliación de ese turno al origen sigue pendiente de decisión.
