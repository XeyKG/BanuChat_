# Soporte y reporte de incidencias

## 1. Alcance de la ayuda

El soporte del Programa Demo de Aprendizaje Digital orienta la descripción de dificultades durante una demostración. Una incidencia puede ser una instrucción ambigua, un resultado inesperado o una imposibilidad de continuar una práctica. Este documento no crea una mesa de atención ni promete tiempos de resolución o canales externos.

La primera distinción consiste en separar una duda de interpretación de una dificultad para realizar la práctica. Una consigna ambigua requiere precisar su significado; un material que no puede leerse requiere describir qué parte falta. Explicar primero esa diferencia ayuda a no buscar una solución para un problema distinto.

El asistente puede ayudar a organizar una descripción y remitir al material pertinente, pero no abre solicitudes de atención ni confirma que alguien las haya recibido. Esta orientación tampoco promete plazos de resolución. Su propósito es aclarar el siguiente paso posible con la información disponible.

## 2. Describir lo observado

Una descripción útil indica qué se intentaba hacer, qué ocurrió y qué se esperaba según el material. Conviene utilizar títulos o claves del escenario para identificar el contexto. No es necesario incluir información personal, rutas del dispositivo o capturas de servicios ajenos para explicar una dificultad de la práctica.

Debe distinguirse observación de interpretación. “La lista aparece vacía” describe un resultado visible; “se borraron todos los datos” sería una conclusión que necesita evidencia adicional. Esta separación permite revisar el problema sin incorporar una causa imaginada desde el comienzo.

Cuando se desconozca un detalle, se señala como desconocido. Una reconstrucción aproximada no debe presentarse como registro exacto de lo sucedido. También resulta útil indicar si el comportamiento pudo repetirse una vez en condiciones similares, sin insistir indefinidamente ni ejecutar acciones que puedan duplicar contenido.

## 3. Comprobaciones iniciales

Antes de repetir una consulta se revisan el perfil seleccionado, los filtros y la necesidad concreta. Una lista de progreso sin coincidencias puede deberse al estado elegido. Un calendario vacío puede corresponder al rango consultado. Estos resultados no prueban por sí solos una falla del sistema.

Si la dificultad se refiere a un documento, indique su título y la sección afectada. Describa si el problema es que no se entiende una instrucción, falta un insumo o no puede leerse una parte. Son observaciones distintas y cada una necesita una aclaración diferente.

Cuando una acción produzca un resultado incierto, revise lo visible antes de repetirla. Conserve identificado el último paso que puede confirmar. Si no sabe si el resultado quedó completo, describa esa incertidumbre en lugar de reconstruir una secuencia que no observó.

## 4. Información que no debe compartirse

La descripción de ayuda debe excluir contenido privado y detalles que no sean necesarios para comprender la práctica. Si aparece información sensible, no la copie para ilustrar el problema. Puede explicar de forma general qué tipo de contenido apareció y detener el paso afectado.

Para un ejercicio ficticio suele bastar con el nombre del material, el paso realizado y una descripción segura del resultado. Un ejemplo puede reformularse usando etiquetas inventadas, siempre que se indique que es una reconstrucción. No se utiliza información real para hacer el reporte más convincente.

Tampoco se solicita autenticación institucional ni acceso a cuentas externas para resolver una duda del escenario. Si una instrucción parece exigirlo, debe tratarse como una inconsistencia del material y someterse a revisión, no como una autorización para ampliar el alcance de la demostración.

## 5. Revisión de una incidencia

Para aclarar una incidencia, contraste la instrucción con el resultado esperado del ejercicio. Si una tarjeta pide clasificar pero no define un criterio, señale esa falta concreta. Es más útil precisar el punto de duda que afirmar que todo el material es incorrecto.

Una aclaración útil explica qué término o paso estaba ambiguo y cómo se puede continuar. No necesita atribuir responsabilidad personal. Después se comprueba que la propuesta encaje con el resto de la consigna y no resuelva una dificultad creando otra en el paso siguiente.

Si existen varias interpretaciones posibles, descríbalas brevemente y señale cuál necesita confirmar. No cambie el objetivo de la actividad solo para completar el ejercicio. Cuando falte una indicación indispensable, el paso permanece pendiente hasta contar con información suficiente.

## 6. Continuación segura

Después de aclarar una incidencia, se retoma la práctica desde un punto conocido. Resulta conveniente conservar una copia de trabajo y verificar qué parte del resultado sigue siendo válida. No debe suponerse que la aclaración corrigió automáticamente todos los borradores o actualizó el progreso del perfil.

Si la dificultad persiste, puede dejarse pendiente el paso afectado y continuar únicamente con tareas independientes. No se rellena un resultado faltante para aparentar una ejecución completa. La limitación observada forma parte de la descripción honesta de la práctica.

La ayuda termina cuando el siguiente paso está claro o cuando se reconoce qué información falta para decidirlo. No toda dificultad puede resolverse con los materiales disponibles. Una explicación que delimita el problema y evita acciones inseguras es preferible a una solución inventada.
